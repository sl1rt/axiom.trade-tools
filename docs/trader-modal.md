# Открытие модалки трейдера

## Открытие из результатов расширения (0.3.8)

Проверен штатный путь через общий поиск Axiom: Search by token or CA → поле Search by name, ticker, CA, or wallet → Wallets → полный адрес → строка результата. В живой вкладке Robinhood этим путём открылась модалка нужного кошелька с History; адрес подтверждён explorer-ссылкой. Переход не меняет URL страницы.

Этот путь реализован в `src/wallet-open.ts`. Адреса в панели оформлены как кнопки со стилем ссылок, поскольку открывают модалку, а отдельного URL кошелька не обнаружено. Расширение нажимает кнопку View wallet внутри строки: у самого контейнера строки нет обработчика открытия. До этого читается полный адрес её Copy; после открытия повторно сверяются адрес и сеть по Open in BSCScan / Solscan / RH Scan. Затем включается Max → History → Opened ↓. Пустая History допустима.

Клик во время анализа прерывает его и ждёт завершения очистки. Повторный клик во время открытия заблокирован; есть отмена, тайм-ауты, проверка смены страницы и ручного изменения поиска. Предыдущая модалка при явном выборе другого кошелька закрывается штатной кнопкой с ожиданием анимации.

Для автоматического обхода ранних покупателей по-прежнему используется `UiSource.open()` и таблица транзакций. Механизм открытия через поиск не читает внутреннее состояние Axiom и не обращается напрямую к API.

## Исследование внутреннего механизма

В расширении `UiSource.open()` находит строку по ID транзакции и вызывает `current.button.click()`. Затем ждёт модалку, получает полный адрес через Copy и проверяет её принадлежность. Это текущий рабочий путь.

В сохранённых публичных скриптах Axiom найден `TraderScannerModal`. Обработчики кнопок передают ему `walletAddress` и `chain`, открывая через `openGlobalModalAtom` (React/Jotai). Реализация глобальной модалки очищает предыдущий контент и создаёт новый с увеличенным `key`. `updateGlobalModalOptionsAtom` меняет настройки оболочки, но не адрес кошелька.

`TraderScannerModalBody` обновляет данные при изменении walletAddress/chain. `initScannerAtom` задаёт кошелёк и сеть, сбрасывая вкладку на Active Positions; `cleanupScannerAtom` очищает состояние после размонтирования. Поэтому смена только видимого адреса в DOM не переключит History на нужный кошелёк.

Готовое DOM-событие для открытия трейдера в просмотренных модулях не найдено. События wallet-transfer и wallet-drag-start/end относятся к управлению списками отслеживания, а не к этой модалке.

Технически переключение существующей модалки через внутренний store выглядит возможным, но это вывод из статического кода, без проверки прототипом. Такой способ зависит от внутренних модулей и требует синхронной смены адреса, сети, источника History и проверки принадлежности уже загруженных строк. Он не включён в расширение: текущая версия продолжает работать через кнопки интерфейса.

Источники локального исследования: `23rps3-r2snw_.js` (обработчик открытия), `3rfwkurcrlxbk.js` (глобальная модалка), `2-4e9gjgx1ygh.js` (оболочка), `2n5cyk6b77e5p.js` (обновление данных), `1bcpqa0uam5qh.js` (состояние scanner). Хеши принадлежат просмотренной сборке и могут меняться; сторонние скрипты в репозиторий не включены.
